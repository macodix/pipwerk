- Arbeitspaket: `wp01` ([Plan](../../plan.md))

- Zweig: `ablauftest/wp01-04`
- Ausgangscommit: Stand des Arbeitszweigs `ablauftest/wp01` mit diesem Auftrag. Der Softwarearchitekt nennt ihn beim Start vollständig.
- Grundlage: Prüfbericht der QA [reviews/2.md](../reviews/2.md), Befund B4; `components/pipwerk-studio/scripts/testenv` (Funktion `url_host`, Meldungen von `start` und `status`); [Anwenderdokumentation](../../../../docs/user/pipwerk-studio.md), Abschnitt 2

## Ziel

Abschnitt 2 der Anwenderdokumentation beschreibt die Adresse im Browser und die Option `--host` so, wie sich das Testumgebungsskript verhält.

## Umfang

1. Schritt 2 „Öffnen“ lautet sinngemäß: Rufen Sie im Webbrowser die Adresse auf, die das Skript am Ende des Starts nennt. Ohne `--host` ist das `http://127.0.0.1:<Port der Oberfläche>/`. `components/pipwerk-studio/scripts/testenv status` nennt die Adresse ebenfalls. Der Satz „Nur wenn Sie beim Start mit `--host` eine andere Adresse des Rechners angegeben haben, gilt diese Adresse.“ entfällt.
2. Ein eigener Absatz nach den vier Schritten beschreibt den Zugriff von anderen Rechnern:
   - Ohne `--host` ist pipwerk Studio nur vom eigenen Rechner aus erreichbar.
   - Der vollständige Befehl mit `--host` steht ausgeschrieben da, zum Beispiel `components/pipwerk-studio/scripts/testenv start --frontend-port <Port der Oberfläche> --backend-port <Port des Hintergrunddienstes> --host 0.0.0.0`.
   - Was `0.0.0.0` bedeutet, steht dabei: alle Netzwerkadressen des Rechners.
   - Auf dem eigenen Rechner gilt weiter die Adresse, die das Skript nennt.
   - Andere Rechner verwenden die Netzwerkadresse oder den Namen des Rechners statt `127.0.0.1`.
   - Der bisherige Sicherheitshinweis bleibt inhaltlich erhalten: keine Anmeldung, nur in einem vertrauenswürdigen Netz.
   - Stimmt eine Aussage nicht mit dem Code von `url_host` und den Meldungen von `start` und `status` überein, gilt der Code. Weiche dann ab und nenne die Abweichung im Ergebnis.
3. Glossar: Netzwerkadresse (mit `127.0.0.1` als Adresse des eigenen Rechners) und Hostname oder Name des Rechners, falls verwendet. Der Fließtext verweist auf das Glossar.
4. Abschnitt 4a der technischen Dokumentation wird nur angeglichen, wenn er einer dieser Aussagen widerspricht.

## Nicht-Umfang

Keine Änderung an Code, Tests und Skripten. Prüfskript und Abschnitt 6.4 gehören dem Tester Funktion.

## Technische Abnahmekriterien

1. B4 ist behoben. Jede Aussage zu Adresse und `--host` stimmt mit dem Code des Testumgebungsskripts überein.
2. Jeder Befehl in der Anwenderdokumentation ist so ausführbar, wie er dasteht.
3. Das Prüfskript besteht.
4. Ein Commit im Zweig `ablauftest/wp01-04` auf GitHub. Im Ergebnis wird er vollständig genannt.
