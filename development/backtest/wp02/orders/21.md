## Ziel

Die Browsertests von `components/pipwerk-replay/frontend` laufen mit den Browsern, die im gemeinsamen Cache für Playwright 1.64.1 installiert sind.

## Umfang

1. In `components/pipwerk-replay/frontend/package.json` `@playwright/test` von `1.63.0` auf `1.64.1` setzen (feste Version, wie bisher), `package-lock.json` mit `npm install` aktualisieren. Keine weiteren Abhängigkeiten ändern.
2. Aufrufen von `playwright install` ist verboten, in jeder Form. Fehlt ein Browser trotzdem, brich ab und nenne im Ergebnis die genaue Fehlermeldung; keine Wiederholung.
3. Alle Stellen der Dokumentation, die `1.63.0` nennen, auf `1.64.1` bringen (`docs/technical/pipwerk-replay.md`, `components/pipwerk-replay/README.md`, Änderungsnachweis).
4. Das Prüfskript `components/pipwerk-replay/scripts/check` ausführen, einschließlich Browsertests, im Hintergrund. Das Ergebnis jedes Browsertests (bestanden/nicht bestanden, Anzahl) im Ergebnis nennen. Scheitert ein Browsertest wegen des Inhalts, behebe die Ursache im Code der Oberfläche, soweit sie in Auftrag 20 liegt; ein Fehler im Backend gehört ins Ergebnis, nicht in den Code.

## Nicht-Umfang

- Backend, Bibliothek, Web-API, `development/`, `docs/design/`, Spezifikation und Plan.
- Das Verhalten von „Dateien behalten“ bei gleichem Dateinamen (wird nach einer Ergänzung der Spezifikation gesondert beauftragt).

## Technische Abnahmekriterien

1. `package.json` und `package-lock.json` nennen `@playwright/test` 1.64.1; kein Verweis auf 1.63.0 im Zweig.
2. Das Prüfskript endet mit Exitcode 0 einschließlich aller Browsertests, oder das Ergebnis nennt genau, welche Browsertests aus welchem Grund scheitern.
3. Kein Aufruf von `playwright install`.
4. Ein Commit im Zweig `backtest/wp02-21` auf GitHub, im Ergebnis vollständig genannt.

Befehle über 10 Minuten laufen im Hintergrund. Befehle enthalten keine Variablen. Fehlende oder unklare Vorgaben meldest du im Ergebnis an den Entwicklungsleiter.
