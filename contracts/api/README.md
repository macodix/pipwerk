# API Contracts

Versioned HTTP API contracts.

- `pipwerk-studio/v1/openapi.json`: the public web API of pipwerk Studio under `/api/v1/`. The file is generated from the application and limited to the paths below `/api/v1/`. How it is generated and what the web API does is described in `docs/technical/pipwerk-studio.md`, section 5.
- `pipwerk-replay/v1/openapi.json`: the web API of pipwerk replay under `/api/v1/` (test accounts, and the data stock of historical price data with overview, import, completeness and acquisition from a source under `/api/v1/market-data/`; later orders add the test runs). The file is generated from the application and limited to the paths below `/api/v1/`; the technical endpoint `/api/health` and the internal endpoints below `/api/replay/` (settings language and default source, revision) are not part of it, like `/api/studio/` of pipwerk Studio. A test compares the file with the application and fails on a deviation. How it is generated and what the web API does is described in `docs/technical/pipwerk-replay.md`, section 5.
- `pipwerk-fetch/v1/openapi.json`: the interface of a source of historical market data (`pipwerk-fetch-mt5` is the first one): `POST /api/v1/fetch` for candles, ticks and the details of an instrument, `GET /api/v1/health`. Every request carries the shared key as `Authorization: Bearer <key>`. The answer holds the file in the JSON format of the import (`contracts/market-data/v1/`) and the rows that were left out. The file is generated from the program (`python -m pipwerk_fetch_mt5.contract`); `pipwerk-fetch/v1/examples/` holds one request and one answer of each kind and two errors. What the interface does is described in `docs/technical/pipwerk-fetch-mt5.md`, section 6.
