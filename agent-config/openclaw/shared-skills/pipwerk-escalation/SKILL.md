# pipwerk-escalation

## Zweck

Entscheidungsbedarf der zuständigen Rolle zuordnen, statt außerhalb der eigenen Zuständigkeit zu raten.

## Verfahren

Ordne die offene Frage ein:

- fachliche Anforderung, Verhalten, Scope oder Abnahmekriterium: Projektleiter; bei notwendiger Auftraggeberentscheidung zum Nutzer;
- Architektur innerhalb bestehender dokumentierter Regeln: Softwarearchitekt;
- neue oder geänderte grundlegende Architekturfestlegung: Softwarearchitekt meldet an Projektleiter zur Entscheidung mit dem Nutzer;
- normales Implementierungsdetail innerhalb der Vorgaben: Entwicklungs-Agent;
- QA-Befund: QA beschreibt den Befund, entscheidet aber nicht die Korrekturlösung.

Formuliere bei einer Eskalation knapp:
1. betroffene Referenz;
2. konkrete offene oder widersprüchliche Frage;
3. warum die eigene Zuständigkeit nicht ausreicht;
4. welche Rolle entscheiden muss.

Keine vermutete Entscheidung vorwegnehmen.
